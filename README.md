# Lyberch Portfolio v9.2

Next.js portfolio with a protected admin dashboard and Supabase persistence.

## Admin login — fixed

Run this from the project root:

```bash
npm install
npm run setup-admin
npm run dev
```

Use the exact email and password you entered during `setup-admin`.

The setup script now:
- stores bcrypt hashes in `.env.local` and `data/admin.json`;
- preserves your existing Supabase environment variables;
- preserves an existing `AUTH_SECRET` so rerunning setup does not invalidate sessions;
- makes environment-variable hashes the production source of truth, so a stale local `data/admin.json` cannot override Vercel settings.

### Vercel

Do **not** upload `.env.local` or `data/admin.json`.

In Vercel → Project → Settings → Environment Variables, add:

- `ADMIN_EMAIL_HASH`
- `ADMIN_PASSWORD_HASH`
- `AUTH_SECRET`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

The three admin values are generated by `npm run setup-admin`.

Then redeploy the project.

## Supabase

Run `supabase-schema.sql` in the Supabase SQL Editor before using the dashboard. The project API stores projects in `public.projects`.

## Node.js

Use Node 22 or Node 24. This project intentionally does not support Node 26 yet.

## Security

The admin cookie is HTTP-only, SameSite=Strict, signed with HMAC, and expires after 8 hours. Login attempts are rate-limited per IP. Project writes require authentication and same-origin requests.

## If you see “Database is not configured or unavailable”

This version works locally even before Supabase is configured: it reads and writes `data/projects.json` when Supabase variables are absent. This fallback is for local development only because Vercel's filesystem is not persistent.

For Vercel production, add these server-only variables:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
```

Then run `supabase-schema.sql` once in Supabase SQL Editor and redeploy Vercel. Never use the service-role key in a `NEXT_PUBLIC_*` variable.
